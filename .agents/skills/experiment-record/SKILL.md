# 实验建档与原始数据归档

实验记录与数据放在一起，保证每份结果都能追溯到实验目的、参数和具体跑测。执行实验之前完成建档，不要等结果生成后再补写计划。

## 目录约定

1. 定位实际实验项目根目录，沿用其 `results_local`（这是一个目录名，不是 `results/_local`）。例如 Tajfel 使用 `Project/Tajfel-git/results_local`。用户明确指定位置时遵从指定位置。
2. 新实验创建 `results_local/YYYYMMDD_HHmmss_实验短名/`。同秒重名时加序号，禁止覆盖已有目录。
3. 实验根目录保存 `实验记录.md`。同一目的下的补跑、重试和新增种子沿用该实验目录；目的或设计发生实质变化则新建实验目录，在记录中链接前一实验。
4. 每次执行使用新的 `runs/run_001/`、`runs/run_002/` 等目录。并行批次提前分配不同编号，由协调者统一更新根记录，避免覆盖。

```text
results_local/YYYYMMDD_HHmmss_实验短名/
├── 实验记录.md
├── runs/
│   ├── run_001/
│   │   ├── raw/           # 原始输出，保留条件、种子等原有层级
│   │   ├── logs/          # 标准输出、错误和运行日志
│   │   └── parameters.json # 实际生效的参数快照
│   └── run_002/
└── analysis/              # 后续分析、图表、汇总，与原始数据分开
```

## 执行前

- 从用户要求、方案和配置中提取实验目的与测试内容；不明确的关键设计先澄清，不能凭空编造。能确定的内容先写入记录。
- 先创建实验目录、根记录和本次跑测目录，再启动进程。新建记录状态为“已计划”，启动时改为“运行中”。
- 记录实际时间与时区，默认沿用当前环境时区；分别标明计划时间、实际开始和结束时间。尚未发生的时间留“待开始/待结束”，不能用建档时间冒充开始时间。
- 保存完整命令、工作目录、配置文件及实际参数快照，包含显式参数和影响结果的默认值。至少检查：条件/实验臂、矩阵、模型供应商与模型名、真实模型或 scripted 模式、智能体数、步数、种子列表、交流轮次、采样参数、并发、重试、超时及输出路径。不适用的项标明不适用；无法核实的值标明未知及原因。
- 记录代码提交、分支和是否存在未提交改动；必要时保存与本次运行有关的差异。记录依赖版本或环境标识，便于复现。
- 不把密钥、令牌、密码写入命令记录、配置快照或日志；环境变量只记录名称和非敏感值。
- 使用程序真实支持的输出选项，将原始数据指向本次 `raw/`。先检查帮助或实现，不虚构参数。不支持输出重定向时，用隔离的工作目录或运行后复制并核对文件；在记录中说明临时来源及归档状态。
- 若在 WSL 或远程环境运行，结合相应访问技能，记录执行路径和本地归档路径。不能绕过权限或为归档擅自改变计算位置；尚未归档时明确标为“待归档”。

## 每次跑测后

无论成功、失败、中断或只完成部分条件，都更新同一份根目录 `实验记录.md`：

1. 追加本次执行明细，保留此前所有批次和参数历史，不用最新结果替换旧记录。
2. 更新实际结束时间、耗时、状态、退出码（可取得时）、完成/计划条件与种子数。
3. 写入原始数据、日志、参数快照的相对链接，检查文件是否存在、输出数量和预期是否一致。长时间运行时记录最近检查时间与当前进度；异步进程启动不等于实验完成。
4. 记录错误、重试、缺失输出、回退率等可获得的质量指标；未知就注明未知，不因缺少错误日志而宣称成功。
5. 概述本次观察与下一步，区分事实和解释。scripted 流程测试不能当作真实模型的行为结论。
6. 更新根记录顶部的总状态和最后更新时间。重试使用新批次目录并关联失败批次，保留失败时的原始数据。分析产物写入 `analysis/`，不修改原始数据。

若仅被要求创建技能、准备计划或查看结果，不自行发起实验。既有结果需要补录时标明“历史补录”，保留可验证的来源时间，不伪造事前记录。

## 实验记录模板

创建时使用以下结构，按实际实验补充必要字段：

```markdown
# 实验记录：<实验名称>

- 实验编号：<目录名>
- 项目：<名称与路径>
- 创建时间：<带时区的实际时间>
- 最后更新时间：<带时区的实际时间>
- 总状态：已计划 / 运行中 / 部分完成 / 已完成 / 失败 / 已中断 / 待归档

## 实验目的
<研究问题、预期检验的假设或流程验证目标>

## 跑测内容
<实验设计、对照、条件、范围、预期输出和完成标准>

## 环境与代码
<运行位置、代码版本、未提交改动、依赖与模型信息>

## 跑测索引
| 批次 | 内容 | 开始时间（含时区） | 结束时间（含时区） | 状态 | 数据位置 |
|---|---|---|---|---|---|
| run_001 | <内容> | 待开始 | 待结束 | 已计划 | [原始数据](runs/run_001/raw/) |

## 跑测明细

### run_001
- 本次目的与内容：
- 与上一批次的关系及参数变化：首次运行 / <变化和原因>
- 计划时间：
- 实际开始时间：待开始
- 实际结束时间及耗时：待结束
- 工作目录与执行命令：
- 实际参数：<列出关键参数，并链接 parameters.json>
- 状态、退出码与完成范围：
- 原始数据与日志：<相对链接>
- 质量检查、异常及处理：
- 观察与后续安排：

## 实验总体进展
<已完成范围、待完成范围、结论限制；每次跑测后更新>
```

## 完成检查

交付时确认：执行前已有记录；每个批次可追溯目的、内容、时间和参数；原始数据在对应实验目录内或明确标记待归档；所有执行（含失败）都有更新；旧数据和旧记录未被覆盖。向用户提供实验根记录和数据目录链接。
